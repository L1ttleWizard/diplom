# ADR-011: Sample-Domain Trigger Engine, Hysteresis Comparator, and Sweep Modes

## Context
В рамках Wave 14 проекта цифрового двойника осциллографа («Цифровой двойник лабораторного стенда») поставлена задача реализации полноценной системы синхронизации (Trigger Engine). 

В соответствии с фундаментальными правилами архитектуры (`GEMINI.md` Rule 1, 2, 3):
1. **Control Plane и Data Plane должны быть строго разделены**: синхронизация должна осуществляться непосредственно в дискретной временной области выборок (Acquisition / Sample Domain) на частотах 1–5 MSPS, а не поверх прореженного буфера дисплея (Display Buffer).
2. **Параметры временной развертки и захвата**:
   - Фронты синхронизации: нарастающий (`RISING`), спадающий (`FALLING`);
   - Порог срабатывания (`level`);
   - Горизонтальное положение точки триггера на экране (`position` in [0.0, 1.0]), определяющее разбиение окна наблюдения N_window = 10 * timeDiv * fs на пре-триггер (N_pre = round(N_window * P_trig)) и пост-триггер (N_post = N_window - N_pre);
   - Режимы развертки: автоматический (`AUTO`), ждущий (`NORMAL`), однократный (`SINGLE`);
   - Подавление шумов и ложных срабатываний: гистерезисный компаратор (триггер Шмитта) с зоной нечувствительности [V_level - V_hyst, V_level + V_hyst];
   - Время удержания (Holdoff Time) для подавления повторных срабатываний на сложных пачках импульсов;
   - Субдискретная интерполяция (delta in [0, 1)) для устранения фазового дрожания (jitter) при отображении на экране осциллографа.

---

## Problem
1. **Неприменимость синхронизации на уровне буфера дисплея**:
   Если искать фронт синхронизации на уже децимированном буфере отображения (1000 точек):
   - Теряется фазовая информация высокочастотных компонент (стробоскопический эффект и алиасинг);
   - Невозможно реализовать физически корректный пре-триггер произвольной длительности (например, просмотр пред-истории аварийного фронта импульса за 5 мкс до события);
   - Возникает дискретное дрожание осциллограммы (+- 1 пиксель), разрушающее плавность картинки при 60 FPS.
2. **Ложные срабатывания на зашумленных сигналах**:
   Реальные сигналы и модели АЦП содержат тепловой шум и шум квантования. Простой детектор знака производной x[k] > V_level >= x[k-1] вызывает пачки ложных триггеров на медленно нарастающих фронтах.
3. **Асинхронность потокового захвата**:
   При потоковой записи в кольцевой буфер момент обнаружения триггера k_trig требует накопления будущих N_post отсчетов. Если окно пост-триггера еще не поступило в буфер, попытка немедленного чтения приведет к чтению устаревших или неинициализированных данных.

---

## Options
1. **Option A: Синхронизация на дисплейном буфере (Display-domain trigger)**:
   - *Плюсы*: Предельно простая реализация в 20 строк кода на массиве в 1000 точек.
   - *Минусы*: Нарушение `GEMINI.md` Rule 2 ("Запрещено передавать millions of samples через React state" и "Display rate != sample rate"); невозможность точного пред- и пост-триггера; стробоскопические артефакты при частотах сигнала выше половины частоты дискретизации отображения.
2. **Option B: Полноценный Sample-Domain Trigger Engine с триггером Шмитта и пред/пост-буферизацией**:
   - *Плюсы*: Физически точная модель синхронизации цифрового запоминающего осциллографа (DSO); поддержка произвольного пре-триггера (0%..100% ширины экрана); подавление шумов гистерезисом; поддержка субдискретной интерполяции для нулевого джиттера; поддержка режимов AUTO / NORMAL / SINGLE; строгая изоляция в Data Plane.
   - *Минусы*: Более сложная машина состояний захвата и необходимость контроля заполнения буфера перед фиксацией кадра.

---

## Decision
Выбран **Option B: Sample-Domain Trigger Engine**.

### 1. Архитектурный конвейер Data Plane
```text
Raw ADC Samples (Ring Buffer)
            │
            ▼
┌────────────────────────┐
│    TriggerDetector     │ ─── Schmitt Trigger Comparator [Level +- Hysteresis]
│                        │ ─── Slope (Rising / Falling) & Holdoff Counter
└───────────┬────────────┘ ─── Sub-sample Linear Interpolation (delta)
            │ Trigger Event (sampleIndex, delta)
            ▼
┌────────────────────────┐
│     TriggerEngine      │ ─── Pre-trigger verification (N_pre accumulated)
│                        │ ─── Post-trigger completion (N_post arrived)
│                        │ ─── Mode State Machine (AUTO / NORMAL / SINGLE)
└───────────┬────────────┘ ─── Auto-trigger timeout fallback timer
            │ Capture Window [startIdx, count, triggerOffset]
            ▼
┌────────────────────────┐
│  extractDisplayBuffer  │ ─── Anchors trigger point at P_trig * N_points
└───────────┬────────────┘ ─── Eliminates phase drift & jitter
            │ 1000 display points
            ▼
     Display Texture
```

### 2. Математическая модель компаратора (Триггер Шмитта с гистерезисом)
Для предотвращения многократных ложных срабатываний компаратор хранит внутреннее бинарное состояние `_isArmed`:
- **Нарастающий фронт (`RISING`)**:
  - Компаратор взводится (`_isArmed = true`), когда входной сигнал опускается ниже нижнего порога:
    `x[k] < V_level - V_hyst`
  - Событие триггера генерируется в момент, когда взведенный компаратор фиксирует пересечение верхнего порога:
    `x[k] >= V_level + V_hyst`
  - После срабатывания `_isArmed = false` и запускается таймер удержания T_holdoff.
- **Спадающий фронт (`FALLING`)**:
  - Взвод: `x[k] > V_level + V_hyst`
  - Срабатывание: `x[k] <= V_level - V_hyst`.

### 3. Субдискретная интерполяция (Zero-Jitter Phase Alignment)
Для точного определения непрерывного момента времени пересечения порога V_level между дискретными отсчетами x[k-1] и x[k] используется линейная интерполяция:
`delta = (V_level - x[k-1]) / (x[k] - x[k-1])`, `delta in [0.0, 1.0)`
Физическое время события триггера:
`t_trig = (k - 1 + delta) / fs`
При формировании буфера отображения смещение delta компенсируется в `extractDisplayBuffer`, благодаря чему фронт сигнала визуально зафиксирован с точностью до доли пикселя.

### 4. Семантика режимов развертки
- **AUTO**: При наличии условий синхронизации генерирует стабильные синхронизированные кадры. Если за интервал времени `autoTimeout` (по умолчанию 100 мс) ни одного фронта не обнаружено (или сигнал постоянный/выключен), принудительно формирует псевдо-синхронный кадр («бегущая развертка»), гарантируя видимость нулевой линии и параметров сигнала.
- **NORMAL**: Обновляет экран исключительно по реальным событиям триггера. При отсутствии триггера экран не обновляется (сохраняется последний захваченный кадр).
- **SINGLE**: Захватывает ровно один полноценный кадр после взвода и первого истинного события триггера, после чего переводит осциллограф в состояние `STOPPED` и замораживает данные.

## Verification & Test Evidence
Разработан полный набор детерминированных тестов:
1. `tests/domain/trigger/trigger-detector.test.ts` (9 тестов):
   - Аналитическая проверка порога и расчетной дельты delta на синусе (1 кГц, 1 В, 1 MSPS);
   - Проверка спадающего фронта (`FALLING`);
   - Проверка прямоугольного сигнала (`SQUARE`);
   - Подавление шума с амплитудой до +-40 мВ при гистерезисе 50 мВ;
   - Время удержания (Holdoff): пропуск паразитных импульсов в течение заданного интервала;
   - Обратный поиск в кольцевом буфере (`findTriggerReverse`);
   - Граничные условия: постоянный ток (DC) выше/ниже порога не вызывает триггера.
2. `tests/domain/trigger/trigger-engine.test.ts` (13 тестов):
   - Корректное разбиение окна захвата при положении триггера 10%, 50%, 90%;
   - Блокировка синхронизации в режиме `AUTO` на периодическом сигнале;
   - Срабатывание таймаута авто-триггера при переходе в постоянный ток (DC);
   - Режим `NORMAL`: обновление при сигнале и полная заморозка кадров при отсутствии триггера;
   - Режим `SINGLE`: одиночный захват, отправка события `ACQUISITION_STOPPED` и переход в `STOPPED`;
   - **Soak-тест на 50 последовательных кадров**: дисперсия смещения триггера равна **0 отсчетов** (абсолютно монолитная стабилизация фазы).
3. Интеграция в сквозной стенд `TestBench` (`tests/application/test-bench.test.ts`):
   - Все 7 сквозных тестов успешно пройдены.
4. Общий регрессионный прогон: **28 тест-сьютов, 272 теста успешно пройдены** (`pnpm test`), 0 ошибок типов, 0 нарушений границ модулей.

---

## Consequences
1. Система оснащена эталонным sample-domain триггерным ядром, соответствующим структуре реальных цифровых запоминающих осциллографов (Agilent, Tektronix).
2. За счет пред- и пост-триггерного анализа оператор может исследовать предысторию переходных процессов в лабораторных экспериментах.
3. Достигнута нулевая фазовая нестабильность на 3D-экране осциллографа при частоте обновления 60 FPS.
